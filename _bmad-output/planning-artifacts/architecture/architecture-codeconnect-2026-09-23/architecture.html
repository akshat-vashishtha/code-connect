Distributed Spring Session Redis Flow

How the Dedicated Gateway and Microservices Share Session State Without Exposing JWTs

Zero Client-Side JWTs
1

Login Request Ingestion (No Cookie)

Student enters email and password on Next.js. The browser issues POST /api/v1/auth/login directly to gateway-service without any auth header.

Browser → gateway-service
2

Credential Verification & Session Creation in Redis

gateway-service verifies hashed BCrypt password against MongoDB. Upon match, Spring Session creates a new session in the shared Redis cache with key spring:session:sessions:<uuid> storing user_id, role, and expiry (7 days).

gateway-service → Shared Redis
3

Opaque Cookie Issued to Browser

Gateway returns HTTP 200 OK with header: Set-Cookie: APP_SESSION=abc123...; HttpOnly; Secure; SameSite=Strict; Path=/. JavaScript has zero access to this cookie, eliminating XSS token theft.

gateway-service → Browser
4

Subsequent API Call Routed via Gateway

User opens a Foothold. Next.js triggers GET /api/v1/curriculum/footholds/101. The browser automatically attaches Cookie: APP_SESSION=abc123.... Gateway verifies that the session is active in Redis, then proxies the request downstream.

Browser → gateway-service
5

Downstream Microservice Reads Shared Session from Redis

Because Gateway forwards the Cookie, curriculum-service (and any other domain service) uses its own embedded spring-session-data-redis filter to read session attributes directly: session.getAttribute("user_id"). No token decoding or secret sharing required!

curriculum-service ↔ Shared Redis
6

Instant Global Invalidation on Logout

When user clicks Logout (POST /api/v1/auth/logout), Gateway invokes session.invalidate(). Redis deletes the session key. Immediately, ANY subsequent request across ALL microservices fails with 401 Unauthorized in O(1) time without token delay.

gateway-service → DEL Redis Key

Asynchronous Kafka Sandbox Execution Pipeline

Zero HTTP Block, Ephemeral Docker Isolation, and Real-Time WebSocket Push

STOMP over WebSocket
A

1. Submission Ingest & Immediate 202 Accepted

Student presses "Run Foothold" in the Monaco Cockpit. submission-service receives the payload, generates a unique submissionId, publishes a JSON event to Kafka topic code.submissions, and immediately returns HTTP 202 Accepted { submissionId } in under 20ms.

submission-service → code.submissions
B

2. Worker Ingestion & Ephemeral Docker Sandbox

sandbox-runner-service pulls the event from Kafka. It invokes the Docker daemon via local socket to spin up an isolated container: docker run --rm --network none --memory 128m --cpus 1.0 codeconnect-runner:java21.

sandbox-runner → Docker Daemon
C

3. Compilation, Test Execution & Hard 3000ms Timeout

Student code is compiled with javac -J-Xmx64m Solution.java and evaluated against test cases with java -Xmx128m TestRunner. If execution exceeds 3000ms, the container process is forcefully killed. Exit code and stdout/stderr are captured.

Ephemeral Box → stdout / stderr
D

4. Kafka Results Topic & Real-Time Client Push

Worker publishes the evaluation outcome to Kafka topic code.results. collab-service consumes this result and pushes it directly into the student's active WebSocket connection at /topic/submissions.{submissionId}.

collab-service → STOMP Push

Enterprise Production Gateway Evolution

Connecting the Dots: How Local Architecture Matures into Cloud Production Infrastructure

Phase 1: Local Kubernetes / MVP

Spring Cloud Gateway as Dedicated Auth & Router

  • Unified Ingress & Auth: gateway-service handles path-based routing, CORS, rate-limiting, and login/session creation.
  • Zero Extra Infra: No complex NGINX / Envoy controllers needed on local machine; simple Helm chart deployment.
  • Shared Redis: Both Gateway and internal services speak the same Java Spring Session serialization protocol natively.

Phase 2: Enterprise Production Scale

Cloud Ingress (Envoy / Kong / ALB) + Auth Service

  • L7 Edge Termination: AWS ALB or NGINX Ingress Controller terminates public TLS certificates and handles DDoS protection (WAF / Cloudflare).
  • External Auth Filter: Envoy / Ingress delegates session verification to gateway-service or dedicated Auth pods via forward-auth.
  • Managed Redis Cluster: AWS ElastiCache / Redis Enterprise with Multi-AZ replication ensures zero downtime failover.
